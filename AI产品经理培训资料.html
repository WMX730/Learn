角色定位：AI产品经理是什么

理解AI时代产品经理的独特价值与核心差异

AI产品经理是技术创新与商业价值的转化枢纽，需同时理解机器学习技术栈和产品方法论，是连接"技术可能性"与"商业必要性"的桥梁。

AI产品经理的六大核心职责

🔍

需求洞察与技术可行性评估

通过NPS调研、用户旅程地图区分真实需求与技术噱头，与算法团队协作评估技术边界，进行ROI分析。

🎨

产品方案设计

主导构建特征体系，针对AI概率性输出设计降级方案，制定置信度阈值与人工审核触发机制。

🔄

模型全生命周期管理

从实验阶段到上线阶段，再到迭代阶段，建立监控指标、处理bad case、推动模型优化。

🤝

跨团队协作

与算法团队用技术语言沟通，与工程团队制定合理SLA，协调标注团队构建领域语料库。

📊

数据闭环建设

建立持续数据反馈机制，将用户高价值交互自动筛选、清洗、标注、回流训练，防止模型衰减。

💰

商业价值转化

将技术指标映射为商业指标，如准确率提升1%如何量化到GMV增长，完成价值闭环。

技术知识图谱

机器学习基础

理解监督学习、无监督学习、半监督学习的适用场景；掌握分类、回归、聚类等基础算法原理；了解模型训练、验证、测试的基本流程。

大模型技术理解

掌握LLM的核心能力（文本生成、对话、推理）；理解RAG、微调、提示词工程等技术方案的优缺点和适用场景。

数据工程基础

技术深度建议

作为AI产品经理，不需要成为算法工程师，但需要"足够的技术理解力"：能够与算法团队进行有效沟通，判断技术方案的可行性，理解模型的能力边界和局限性。

Prompt工程：AI产品的核心竞争力

掌握与大模型有效交互的核心技巧

Prompt不是越长越好，简洁精准才是王道。成功的Prompt都是经过循环打磨出来的。

—— Prompt Engineering实战指南

Prompt四要素框架

🎭

Role（角色）

激活模型特定领域的知识子空间。角色定义越精准，输出质量越高。

# 推荐写法
你是一位专注性能优化的
  Java架构师，有10年经验

# 不推荐写法
你是一个AI助手
📋

Task（任务）

明确要完成的具体动作，使用动词开头，清晰表达目标。

# 推荐写法
请评审以下代码的性能问题
提取文章中的关键论点

# 不推荐写法
关于这个代码< span class="keyword">你说一下
📚

Context（上下文）

提供任务相关的背景信息，帮助模型理解场景限制和前置条件。

# 示例
当前线上QPS 2000
响应时间超过500ms
用户反馈卡顿严重
📐

Format（格式）

指定输出的结构要求，JSON/XML/Markdown等，确保输出可解析。

# 示例
输出JSON，包含
"title"、"summary"
两个字段

六大Prompt核心技巧

🧩

1. 思维链（Chain-of-Thought）

要求模型展示推理过程，特别适用于复杂推理、数学计算、逻辑分析等场景。

在回答之前，先思考：1) 涉及哪些关键变量？ 2) 变量之间什么关系？ 3) 最终答案如何验证？
📝

2. 少样本学习（Few-Shot）

提供1-3个高质量示例，比纯文字描述更有效。示例必须与实际任务同类型，覆盖主要边缘情况。

🏗️

3. 任务分解（Task Decomposition）

将复杂任务分解为多个子任务。可采用静态分解（流程固定）或动态分解（探索性任务），逐步调试优化。

📋

4. 结构化输出（Structured Output）

使用XML标签构建清晰层级，或使用模型原生支持的JSON Mode，确保输出格式稳定可解析。

🔗

5. 链式提示（Prompt Chaining）

将复杂任务分解为多个子任务，每个子任务有独立Prompt，使用标签在提示之间传递输出。

⚡

6. 预填充（Pre-filling）

在结尾加特定字符（如{），强制模型跳过前言直接进入正题，确保输出格式一致性。

Prompt注入攻击防护（重要）

执行层：代码执行环境隔离，API Key严格受限，危险操作额外授权
认知层：区分System Prompt和User Input，使用分隔符包裹不可信数据
决策层：高危操作（修改数据库、发送邮件、转账）执行前触发人工审批

评估体系：构建AI产品的评价标准

建立科学的AI产品效果评估方法

AI产品核心评估指标

🎯

准确率（Precision）

模型预测为正类的样本中，实际为正类的比例。高准确率意味着较少的误杀。

公式：Precision = TP / (TP + FP)
🔍

召回率（Recall）

实际为正类的样本中，被模型正确预测的比例。高召回率意味着较少的漏网。

公式：Recall = TP / (TP + FN)
⚖️

F1 Score

准确率和召回率的调和平均数，在两者之间取得平衡。

公式：F1 = 2 × Precision × Recall / (Precision + Recall)
📊

ROC-AUC

衡量模型在不同阈值下的分类能力，不受类别不平衡影响。

评估体系建设步骤

1

制定评估标准（Baseline）

明确"好回答"的标准是什么，定义不同场景下的质量要求。这是最核心也是最困难的一步。

2

构建评测集

收集数百至数千个真实场景问题，覆盖主要场景和边缘情况。评测集需要持续维护和更新。

3

批量测试与结果分析

对模型进行批量测试，量化模型表现。持续给模型"出考卷"，监控模型效果变化。

4

LLM-as-a-Judge

使用大模型作为"阅卷人"评估输出质量，提升评估效率。可结合人工复核确保准确性。

AI产品经理的价值：Trade-off决策

评估体系的核心目的是帮助做出决策：
• RAG vs 微调：哪个方案更适合当前场景？
• 速度 vs 准确率：在响应延迟和效果之间如何取舍？
• 通用模型 vs 专用模型：根据业务需求和成本进行权衡

新人常见误区

❌ 过度承诺：避免在POC阶段承诺100%准确率
❌ 技术本位：警惕陷入纯算法优化而忽视用户体验
❌ 数据漠视：未建立持续数据闭环将导致模型衰减
❌ 功能堆砌：AI产品界面极简，体验核心在模型而非界面

附录：核心术语表

LLM (Large Language Model)
大语言模型，能够理解和生成人类语言的大型神经网络模型。
Prompt
提示词，用户向AI模型输入的指令或问题，是与AI交互的核心界面。
RAG (Retrieval-Augmented Generation)
检索增强生成，结合外部知识库检索与LLM生成的混合架构。
Fine-tuning
微调，在预训练模型基础上使用特定数据进行调整优化。
幻觉 (Hallucination)
AI模型生成看似正确但实际错误或虚构的内容。
数据飞轮
通过用户行为数据持续优化模型，形成正向循环的系统。
Baseline
基准线，作为比较基准的初始模型效果，用于衡量改进效果。
Bad Case
模型表现不佳的具体案例，是模型优化的重要输入。
